# Leakage statement

**Source.** One file, `aa_dataset-tickets-multi-lang-5-2-50-version.csv` from HF dataset `Tobi-Bueck/customer-support-tickets`, revision `ddf1c81a5475992c4fa6752bf1e8b4e31f07bbeb`, SHA-256 `f187c090e59581c2bbf3aa1377c8db4dd647464ecf2ae51bf8966e42e0ed6bc0`. `scripts/download_data.py` exits non-zero on a hash mismatch. The other two CSVs in that repo are not used: one repeats 8,395 bodies of the main file (`docs/D1_decisions.md`, D1-01).

**Split** (`scripts/make_split.py`). Fill null subject and answer, decode literal `\n`, drop rows whose stripped, lowercased body was already seen (28,587 raw rows, 15 removed, 28,572 kept), shuffle with `random_state=42`, assign `TKT-00000`.., first 80% is the KB. KB 22,857 (`TKT-00000`..`TKT-22856`), holdout 5,715 (`TKT-22857`..`TKT-28571`). The script checks the source hash, these counts, boundary IDs and one spot ticket before writing, and writes nothing on any mismatch. `tests/test_split_contract.py` re-derives the split from the raw CSV without importing the script and compares every row.

**Three files, who reads what** (`data/processed/`, gitignored, regenerated by the scripts):

| file | columns | read by |
|---|---|---|
| `kb_train.parquet` | all, incl. answer | training, retrieval index, drafting |
| `test_inputs.parquet` | `ticket_id`, `subject`, `body` | inference on the holdout |
| `test_labels.parquet` | `ticket_id`, `type`, `queue`, `priority`, `language` | `scripts/score.py` only |

Holdout answers are never written to disk outside the raw CSV. For tuning and calibration the KB is split again, so neither needs holdout labels (`data/processed/kb_partitions.parquet`: fit 18,285, calib 2,286, val 2,286; `reports/kb_partitions_summary.md`).

**Scorer checks** (`scripts/score.py`). It hashes the predictions file first and records the SHA-256 and git commit in every report. It rejects the whole file on missing, repeated or unknown ticket IDs, nulls in required columns, labels never seen in kb_train, confidences outside [0, 1], and any holdout ID (or any ID not in kb_train) in `retrieved_ids` or `cited_ids`.

**Index membership.** `scripts/leakage.py` `assert_kb_only(ids)` raises `LeakageError` (an `AssertionError` subclass, so it survives `python -O`) if any ID is a holdout ID or not in kb_train. The retrieval index must pass it before release (`docs/D1_decisions.md`, D1-27); not yet wired in as of this commit. Tests: `tests/test_leakage_helpers.py`.

**Duplicate audits** (neither reads `test_labels.parquet`):

- Near-copies: MinHash on word 5-grams, verified by exact Jaccard >= 0.85, flags 12 of 5,715 holdout tickets. An exact all-pairs scan finds the same 12. `reports/near_dup_audit.md`, `reports/near_dup_holdout_ids.txt`.
- Paraphrase twins: word 1-2 gram TF-IDF fit on the KB, cosine >= 0.8 to any KB ticket, flags 520 (9.1%). `reports/twin_audit.md`, `reports/twin_holdout_ids.txt`.

Both stay in the canonical split. Every run is scored on the full holdout and with each list excluded, side by side in `reports/<run>/summary.md`. For the TF-IDF baseline, queue macro-F1 is 0.587 full, 0.587 without near-copies, 0.555 without twins (`reports/tfidf_logreg/summary.md`).

**Reproduce**

```bash
python scripts/download_data.py && python scripts/make_split.py && python scripts/make_partitions.py
python scripts/dup_audit.py && python scripts/twin_audit.py
python -m pytest -q
python scripts/baseline_tfidf.py && python scripts/run_eval.py data/predictions/tfidf_logreg.parquet --run-name tfidf_logreg
```
