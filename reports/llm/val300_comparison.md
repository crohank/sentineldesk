## Comparability notes

Held equal across rows:

- ticket IDs: the same 300, asserted for every row (the script stops on any difference)
- training data / few-shot pool: fit partition (18285 tickets); kb_extra is not used
- few-shot neighbours: k=8, word 1-2 gram TF-IDF over greeting-stripped text; each LLM run's stored `fewshot_ids` are asserted equal to the rebuilt neighbours, and the kNN row votes over exactly that set (ties go to the most similar neighbour's label)
- prompt_version: classify-v1; temperature 0 (set in `scripts/gemini_client.py`); structured JSON output with the same label enums

Differs:

- gemini-3.8-flash: thinking low, $0.75 in / $3.75 out per 1M tokens, run 2026-11-21T17:26:07Z
- gemini-3.5-flash-lite: thinking minimal, $0.30 in / $2.50 out per 1M tokens, run 2026-11-21T17:28:43Z
- thinking level: minimal for gemini-3.5-flash-lite because that is its lowest; low for gemini-3.8-flash and gemini-4-carbon because they reject minimal (`reports/llm/smoke.md`)
- model size and price: the models are not the same size, so a gap mixes capability and cost
- local rows are deterministic; LLM rows are temperature 0 but not guaranteed bit-identical on rerun
